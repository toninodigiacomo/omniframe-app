# OmniFrame

# Image AI REST Gateway — Functional Specifications & Secure by Design

An API-first artificial intelligence gateway dedicated to image generation and transformation (text-to-image, image-to-image, etc.). It is built to support creative freedom, including erotic art and artistic nudity (lingerie, nude models), while enforcing strict access control, ephemeral data retention, and enterprise-grade application security.

---

## 1. Project Overview & 3-Tier Architecture
The system relies on an **API-First 3-Tier Architecture**:
1. **Web UI (Frontend):** A lightweight client layer serving solely to facilitate user interaction.
2. **REST API Gateway (Backend - PHP 8.2 / Apache):** The core engine handling all business logic, route fallbacks, input validation, and communication with external AI providers.
3. **MariaDB (Database):** The data tier storing user roles, invitation tokens, provider credentials, and image retention TTLs.

Everything in the application revolves around the **REST API**. Any action performable in the Web UI is powered by underlying API endpoints.

## 2. "Secure by Design" Principles
### A. Authentication & Session Security
* **Single-Use Token Invitations:** Account registration requires a high-entropy, single-use cryptographic token generated by an administrator. Tokens expire after a set TTL and are permanently invalidated once consumed.
* **Password Hashing:** Passwords are hashed using strong algorithms (`Argon2id` or high-cost `bcrypt`).
* **Session Management:** Hardened session cookies (`HttpOnly`, `Secure`, `SameSite=Strict`) with automatic ID regeneration on privilege changes.
### B. Application Hardening (OWASP Top 10)
* **SQL Injection Prevention:** Exclusive use of prepared statements with parameter binding (PDO) for all database operations.
* **XSS Mitigation:** Strict output escaping (`htmlspecialchars` with UTF-8) and a restrictive `Content-Security-Policy` header.
* **CSRF Protection:** Anti-CSRF tokens validated on all state-changing API endpoints.
* **HTTP Security Headers:** Enforcement of `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: strict-origin-when-cross-origin`.
### C. Storage & File Security
* **Upload Folder Isolation:** Complete execution suppression (PHP, CGI) in the `/uploads/` directory via Apache server rules.
* **Anonymized File Naming:** Images are assigned non-predictable UUIDs (v4) upon creation, stripping all original metadata.
* **MIME Validation:** Strict binary analysis of API responses (`image/jpeg`, `image/png`, `image/webp`) prior to writing to disk.
### D. Key Management & Logging
* **Encryption at Rest:** External AI provider keys stored in MariaDB are encrypted using **AES-256-GCM**.
* **Zero Client-Side Exposure:** API keys and infrastructure secrets are never sent to or exposed in the Web UI client.
* **Defensive Logging:** Automatic filtering on error/audit logs to prevent accidental credential or token leakage.

### Group 1: User Lifecycle & Authentication

#### `UC-101`: Access Request & Registration via Single-Use Token
* **Actors:** Visitor, Administrator, System (REST API Gateway).
* **Preconditions:** Direct public registration endpoints are disabled.
* **Main Flow:**
  1. The visitor submits an email address via the access request Web UI form calling the API.
  2. The REST API logs the request with `pending_approval` status in MariaDB.
  3. The administrator approves the request via the admin dashboard, triggering the "Approve and Invite" API endpoint.
  4. The REST API generates a high-entropy cryptographic token (64 hex characters) bound to a TTL (e.g., 48h).
  5. A personalized invitation link (`/register?token=...`) is sent to the target email.
  6. The user opens the link; the API verifies token validity, non-expiration, and unconsumed status.
  7. The user submits a password meeting complexity rules to the registration endpoint.
  8. The REST API hashes the password, sets the account status to `active`, and **permanently invalidates the single-use token**.
* **Exceptions:**
  * *Token expired or consumed:* The request is rejected with a secure JSON error response.

#### `UC-102`: User Moderation
* **Actor:** Administrator.
* **Main Flow:**
  1. The administrator navigates to the user management UI.
  2. The Web UI calls administrative API endpoints to fetch user statuses (`pending_approval`, `invited`, `active`, `suspended`).
  3. The administrator performs moderation actions via API calls: token regeneration, temporary account suspension, or deletion.

### Group 2: Image Generation & Data Retention Policy
#### `UC-201`: Image Generation (SFW / Erotic / NSFW)
* **Actor:** Authenticated User (`active` or `admin`).
* **Main Flow:**
  1. The user inputs prompt instructions and configures parameters (aspect ratio, style) in the Web UI.
  2. The Web UI posts the payload to the REST API Gateway, which validates all input fields.
  3. The REST API Gateway dispatches the request to the primary configured AI provider (e.g., Runware, Novita, Together AI).
  4. If the primary provider fails (429 rate limit, timeout, unavailability), the API Gateway automatically falls back to subsequent providers in the priority chain.
  5. Upon receiving the image stream, the REST API verifies the MIME type, assigns an anonymized file name (UUID v4), and writes the file to `/uploads/`.
  6. The API logs an entry in MariaDB with an expiration timestamp set to `NOW() + 24 hours`.
#### `UC-202`: Automatic Image Purge (24h Retention)
* **Actor:** Scheduled Task (Cron Job).
* **Main Flow:**
  1. A scheduled cleanup script runs at regular intervals on the backend server.
  2. The script queries MariaDB to identify records where `expires_at <= NOW()`.
  3. Physical files are unlinked from disk, and corresponding database rows are purged.
#### `UC-203`: Extension of Image Retention
* **Actor:** Administrator.
* **Main Flow:**
  1. The administrator selects a media item in the UI gallery.
  2. The administrator triggers the "Keep indefinitely" action via an API endpoint.
  3. The REST API updates the database record to `expires_at = NULL`, excluding the file from future purge jobs.

---

### Group 3: API Gateway Administration
#### `UC-301`: AI Provider Configuration
* **Actor:** Administrator.
* **Main Flow:**
  1. The administrator submits access tokens and configuration parameters for third-party APIs (Runware, Novita, Together AI, Replicate) via the administrative UI calling API endpoints.
  2. The administrator sets active statuses and priority sequence rankings for provider fallback order.
  3. The REST API encrypts API keys with **AES-256-GCM** before saving them to MariaDB.
